# Spec: Issue #10, empty artist or bracket-only title matches the wrong iTunes preview

## Goal

Make `score()` in `api/_match.ts` return 0 when the plain artist or plain title is empty, so those songs get no preview instead of an unrelated one.

## Decisions (approved)

- Move `plain`, `score` and `ItunesSong` to `api/_match.ts`; `recently-played.ts` imports them. Tests live in `api/_match.test.ts` (underscore files are not deployed by Vercel).
- `score()` also returns 0 when the plain Apple `artistName` is empty (extra test).
- Songs whose artist or title is fully non-Latin lose their preview. Accepted.

## Out of scope

- Any other changes to the matching rules: `VARIANT`, the score weights, the iTunes query, or the `limit`.
- Using the second or later Spotify artist when the first one is missing.
- The API response shape (`RecentlyPlayed` / `PlayedTrack`) and the cache headers.
- UI changes. The page already handles `preview: null`.

## Changes

- `api/_match.ts` (new): holds `plain`, `score`, `ItunesSong` and `VARIANT`, moved unchanged from `api/recently-played.ts`.
  - In `score()`, return 0 when `a`, `ra` or `t` is empty. Put each check right after the value is computed, before the `includes` checks.
- `api/recently-played.ts`: remove the moved code and import `score` and `type ItunesSong` from `./_match.js` (the `.js` specifier is mapped to the `.ts` source by nodenext tsc, Vite and Vitest). It keeps one `GET` handler.
- `api/_match.test.ts` (new): the Vitest unit tests below, importing from `./_match.js`. `vitest.config.ts` already includes `api/**/*.test.ts`, so no config change is needed.

## Tests (Vitest, `describe('score')` and `describe('plain')`)

1. `plain strips brackets, accents and feat. credits`: `plain('Café (Interlude) feat. X')` gives `'cafe'`, and `plain('(Interlude)')` gives `''`.
2. `returns 0 when the Spotify artist is empty`: `score({trackName:'Song', artistName:'Anyone', previewUrl:'u'}, 'Song', '')` is `0`.
3. `returns 0 when the title is bracket-only`: `score({trackName:'Other', artistName:'Artist', previewUrl:'u'}, '(Interlude)', 'Artist')` is `0`.
4. `scores an exact title and artist match highest`: same title and artist gives `4.5`.
5. `ranks the original above a remix when Spotify has the original`: for title `'Song'`, the result `'Song'` scores `4.5` and `'Song (Remix)'` scores `1.5`. Assert both values and that the original is greater.
6. `returns 0 without a previewUrl`: this pins the existing guard.

Pass checks: `npm test`, `npm run typecheck`, `npm run lint`.

## Risks and open questions (all resolved)

- Vercel deploying the test file as a function: resolved by moving the helpers and the test to underscore files (`api/_match.ts`, `api/_match.test.ts`).
- Empty Apple `artistName`: resolved, `score()` returns 0 for it, with an extra test.
- Non-Latin names becoming empty: accepted, those songs lose their preview.
- Exporting from a function file: no longer relevant, the helpers are in their own module.
