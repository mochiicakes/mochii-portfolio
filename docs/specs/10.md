# Spec: Issue #10, empty artist or bracket-only title matches the wrong iTunes preview

## Goal

Make `score()` in `api/recently-played.ts` return 0 when the plain artist or plain title is empty, so those songs get no preview instead of an unrelated one.

## Decisions (approved)

- Move `plain`, `score` and `ItunesSong` to `api/_match.ts`; `recently-played.ts` imports them. Tests live in `api/_match.test.ts` (underscore files are not deployed by Vercel).
- `score()` also returns 0 when the plain Apple `artistName` is empty (extra test).
- Songs whose artist or title is fully non-Latin lose their preview. Accepted.

## Out of scope

- Any other changes to the matching rules: `VARIANT`, the score weights, the iTunes query, or the `limit`.
- Using the second or later Spotify artist when the first one is missing.
- The API response shape (`RecentlyPlayed` / `PlayedTrack`) and the cache headers.
- UI changes. The page already handles `preview: null`.

## Changes

- `api/recently-played.ts`
  - Add `export` to `plain`, `score` and `type ItunesSong`. The bodies stay where they are, so the file still has one `GET` handler.
  - In `score()`, return 0 when `a` or `t` is empty. Put this check right after each value is computed, before the `includes` checks:
    `if (!a) return 0` after `const a = plain(artist)`, and `if (!t) return 0` after `const t = plain(title)`.
- `api/recently-played.test.ts` (new): the Vitest unit tests below. `vitest.config.ts` already includes `api/**/*.test.ts`, so no config change is needed.

## Tests (Vitest, `describe('score')` and `describe('plain')`)

1. `plain strips brackets, accents and feat. credits`: `plain('Café (Interlude) feat. X')` gives `'cafe'`, and `plain('(Interlude)')` gives `''`.
2. `returns 0 when the Spotify artist is empty`: `score({trackName:'Song', artistName:'Anyone', previewUrl:'u'}, 'Song', '')` is `0`.
3. `returns 0 when the title is bracket-only`: `score({trackName:'Other', artistName:'Artist', previewUrl:'u'}, '(Interlude)', 'Artist')` is `0`.
4. `scores an exact title and artist match highest`: same title and artist gives `4.5`.
5. `ranks the original above a remix when Spotify has the original`: for title `'Song'`, the result `'Song'` scores `4.5` and `'Song (Remix)'` scores `1.5`. Assert both values and that the original is greater.
6. `returns 0 without a previewUrl`: this pins the existing guard.

Pass checks: `npm test`, `npm run typecheck`, `npm run lint`.

## Risks and open questions

- **Vercel may deploy the test file as a function.** Vercel treats every non-underscore file in `api/` as a function, so `api/recently-played.test.ts` could ship as `/api/recently-played.test`. Pick one:
  - (a) add a `.vercelignore` with `api/**/*.test.ts`,
  - (b) move the helpers to `api/_match.ts` and the test to `api/_match.test.ts` (underscore files are skipped), or
  - (c) put the test under `src/`.
  - I recommend (b), because the issue allows a small module. Which do you want?
- **The same bug exists on the Apple side.** If Apple's `artistName` becomes empty after `plain()`, then `a.includes(ra)` is always true, which is the same bug. Should `score()` also return 0 when `ra` is empty? The issue doesn't say. Including it is cheap and would add one more test.
- **Non-Latin names become empty.** `plain()` drops everything except `[a-z0-9]`, so artists or titles written fully in Japanese or Korean also become `''`. With this fix those songs lose their preview, where today they may get a random one. That's probably fine, but please confirm.
- **Exporting from a function file.** Extra named exports next to `GET` should be harmless for Vercel and for the dev plugin's `ssrLoadModule`, but this hasn't been checked.
