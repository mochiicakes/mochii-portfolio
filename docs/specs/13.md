# Spec 13: the ocean background, with light rays (deep-ocean rebrand, step 4)

The number is provisional until a GitHub issue exists.

## Goal

Replace the painted ground and water light with an ocean: light rays from the surface at the top, darkest at the bottom, with the paint-reveal intro unchanged.

## Decisions (approved)

- Keep the paint-reveal intro exactly as it is: white paper, brush, prompt, Enter button, `#link` skips it.
- Light rays are React Bits `LightRays-JS-CSS`, added with `npx shadcn@latest add @react-bits/LightRays-JS-CSS`.
- Lily pads are removed.
- Stacked on `t12-sea-angel`. Nothing is pushed.

## Decisions (proposed, please confirm)

- Depth follows scroll: 0 at the top of the page, 1 at the bottom, over at least two window heights, so a short page (Contact) stays near the surface. The prototype's colours: `rgb(22 72 140) / rgb(7 28 70) / rgb(2 7 20)` at the surface to `rgb(5 18 48) / rgb(3 10 30) / rgb(1 2 7)` at the bottom. Each screen is also darker at its foot.
- Rays: `raysColor #9fd0ff`, spread .8, length 1.6, sharpness .45, glow .5, haze .3, speed .6. They lean slightly toward the cursor, pulse on click, and fade to 15% at the bottom. No cursor shadow: it would dim the water round the angel.
- `LightRays` replaces `Crystal`, so the page keeps one WebGL context and two full-screen canvases (rays, angel). Water ripples, stars and glitter go with it.
- The handoff's drifting specks and bubbles are CSS layers, not a third canvas. None of them move under reduced motion.

## Findings from a throwaway trial

- The command needs a `components.json` and an `@/*` path alias. Without them it stops to ask. With them it adds two files, no packages, about 2.5 KB gzipped.
- The JS file needs a small `LightRays.d.ts` to type-check. The TS version fails `react-hooks/refs`.
- The component keeps moving under reduced motion, so we pass speed 0 and turn off follow and pulse: one still frame.
- Its canvas was 776 x 488 for a 1440 x 900 window, about half resolution.
- The surname loses its edge against the first name, because it relied on the `--bleed` shadow. Fixed in spec 14, or here if 14 is delayed.

## Tests (Vitest)

1. `src/lib/depth.test.ts`: 0 at the top, 1 at the bottom, never outside 0-1; a page shorter than three windows doesn't reach 1; a page that can't scroll is 0.
2. `src/App.test.tsx`: the pre-render still contains the paper canvas and the prompt, and no lily pads.

Pass checks: `npm test`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`. In the browser: paint, Enter and `#contact` on desktop and phone; reduced motion is still; no WebGL shows the plain gradient; no JavaScript shows a readable page.

## Risks and open questions

- Phones: the rays animate all the time. Capped at .6 pixel ratio on touch. Unmeasured on a real phone.
- WebGL 2 is needed (Safari 15 and later). Older browsers get the gradient without rays.
